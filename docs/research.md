## 重点差距

| 能力 | 匣流 1.0.0 | 参考方式 | 本轮决策 |
| --- | --- | --- | --- |
| 跨平台归档 | WPF 和 Windows 引擎路径 | 7-Zip 多架构控制台，可一套归档契约调用多个平台二进制 | Windows 桌面继续完整支持，CLI 使用同一核心，原生运行器测真实归档 |
| 脚本消费 | Windows Shell 启动参数，缺少无窗口处理结果 | rclone 等把机器输出与终端错误分离 | CLI 增加 JSON 清单、退出码、校验、取消 |
| 数据保护 | 归档预检与备份依赖链 | restic 的备份校验与恢复职责分立 | CLI 解压预检并经暂存发布，备份全面演练列入待办 |
| 更新信任 | 从 Release Notes 读首个 SHA-256，缺少数字签名 | TUF 绑定目标名、长度、哈希并验证签名；Inno 维持原 AppId 安装 | 内置公钥验证稳定版元数据，官方 Release 锁定资产，保留手动回退 |
| 产品界面 | 首页和专用操作页，关于页显示更新 | PeaZip 的归档内容与动作面板、Vorta 的恢复入口 | 保留工作区布局，补齐更新下载/取消/详情反馈，修复归档文件的预览与提取 |
| 解包边界 | Windows 文件名检查与 7-Zip 输出 | Ark 的插件/工作界面分层，libarchive 集中处理磁盘写入 | CLI 只创建新的输出项，拒绝不兼容条目和覆盖，ZIP/7z 跨平台实测 |
| 安装维护 | 标签构建，无 PR 门禁 | Windows 安装与多平台 CLI 用各自原生 Runner | Windows 走升级、重启、卸载测试，Linux/macOS 验证 CLI |

观察窗口内，上游 7-Zip 发布 26.06。SharpCompress 仍活跃，但匣流生产路径没有调用。K4os 仍由匣流 LZ4 功能使用，升级应以归档回读为门槛。Velopack 提供安装迁移和重启，匣流现有 Inno 安装身份可继续使用。[7-Zip 26.06](https://github.com/ip7z/7zip/releases/tag/26.06) · [SharpCompress](https://github.com/adamhathcock/sharpcompress) · [Velopack](https://github.com/velopack/velopack)
